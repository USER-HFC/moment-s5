Product behavior and merge surface
----------------------------------
The native list prepends an immutable generated catalog with builtin: IDs and
builtIn/readOnly flags. Selection resolves only exact catalog IDs and reads
the packaged assets, copying temporarily into cache for the existing file
parser and deleting that temporary copy. Package presets are independent of
the user-imported files directory and have no deletion operation.

UI uses a new LutPresetList component, displays 内置 and a Chinese unofficial
approximation/SDR input note, and uses the same selection callback for imports.
Imported IDs, names, sorting, ZIP extraction and file storage are unchanged.
The added native.ts metadata fields are optional for existing bridge clients.

CaptureEngine was not modified: live-view frames and rendered.jpg use the
existing LUT path, and original.jpg retains the original camera JPEG bytes.
Only one LutEngine line changes: reuse ARGB_8888 only if isMutable() is true.
Final review found its previous default-decode/setPixels path could attempt to
write an immutable bitmap. The host regression first reproduced the failure,
then passed after the guard. This also fixes the existing imported LUT path.
Contract reference:
https://developer.android.com/reference/android/graphics/BitmapFactory.Options#inMutable
https://developer.android.com/reference/android/graphics/Bitmap#setPixels(int[],%20int,%20int,%20int,%20int,%20int,%20int)

Shared-file edits are focused: list/select hooks in MomentS5Module.java, one
LutPresetList import/render hook in CameraWorkspace.tsx, optional LutItem flags
in native.ts, and the one-line mutability guard in LutEngine.java. Other feature
logic, assets, generation/catalog data and checks live in new files.
